# 社群內容包

一個主題，產出所有平台當天要發的內容。腳本先寫好，其他平台都從腳本改寫，所以每個平台講的是同一件事、同一個比喻，只是長度與語氣依平台調整。

## 1. 找到專案與品牌設定

1. 在 `projects/*/brand.md` 找品牌設定。只有一個就用它；有多個就問使用者是哪個專案；一個都沒有就停下來，請使用者先建立 brand.md，因為沒有人設寫出來的內容會失去辨識度
2. 完整讀完 brand.md：人設、受眾、風格、內容主軸、名單收集方式都會用到
3. 使用者說「第 N 天」或沒給主題時，讀同資料夾的 `plan.md`，從主題表取那一天的主題、主軸與形式
4. 形式（真人或字卡）沒指定時，依 plan.md；plan 也沒寫就用字卡，因為字卡不需要使用者花時間錄影

## 2. 先想清楚核心

動筆前先寫下這四件事（放進總覽檔），後面每個平台都照它寫：

- **一句話重點**：觀眾看完能帶走的一件事，例如「交代 AI 做事，要像交代新人：給背景、給範例、給格式」
- **比喻**：一個生活中的比喻，把概念講白話。這是 brand.md 指定的風格，也是和其他 AI 帳號最大的差別
- **對象情境**：誰在什麼時候會遇到這個問題，例如「週一早上要交週報的上班族」
- **行動呼籲**：依 brand.md 的名單收集方式，例如「留言『指令』領指令包」

一則內容只講一件事。主題太大就只挑最實用的一個切角，其他留給之後。

## 3. 短影音腳本（其他平台的母體）

長度 30～45 秒，口語約 130～200 字（中文口說每秒約 4～5 字）。

**開頭**：寫 3 個不同類型的版本讓使用者挑，並標出推薦的一個與理由。前 2 秒決定觀眾會不會滑走，所以開頭要具體、有衝突：

| 類型     | 寫法               | 例子                            |
| -------- | ------------------ | ------------------------------- |
| 痛點     | 說出觀眾正在煩的事 | 「開完會還要花 1 小時寫記錄？」 |
| 反常識   | 挑戰一個常見想法   | 「AI 回答很爛，問題可能出在你」 |
| 結果先講 | 先秀成果再講方法   | 「這封信讓主管 3 分鐘就回我」   |

**本體**：分 4～6 段，每段寫「口白」與「畫面」。

- 字卡形式：畫面欄寫螢幕上的字，每張不超過 14 字，因為手機直式畫面一行約 14 字
- 真人形式：口白要像聊天，畫面欄寫鏡頭或補充畫面提示，例如「螢幕錄影：貼上指令」
- 比喻放在前半段，先讓觀眾懂，再給方法
- 方法要具體到看完就能照做，能附上指令原文就附
- 講創作者自己的經歷時（作品怎麼做出來、花了多久、遇到什麼問題），只用 brand.md 寫到的事實。brand.md 沒寫的細節不要自己補成故事，改留空格讓本人填，例如「【待 Tristan 補充：ClipNode 最先做的功能】」。個人品牌靠真實故事建立信任，編出來的情節一旦和本人說法不同，就會傷害可信度

**結尾**：行動呼籲加上追蹤理由，例如「追蹤 Tristan，每天一招 AI 白話」。

## 4. 改寫到各平台

讀 [references/platforms.md](references/platforms.md) 取得各平台的字數上限與寫法，再逐一改寫。改寫是重新寫給那個平台的讀者，不是把腳本貼上去：

- **TikTok、YouTube Shorts、IG Reels、FB** 共用同一支影片，各自寫說明文字或標題
- **IG 輪播、小紅書**：把腳本拆成 6～8 張圖卡的文字；小紅書標題要放觀眾會搜尋的關鍵字
- **Threads**：3～5 則獨立貼文，各自能單獨看懂：一則比喻、一則技巧、一則提問或故事，其餘自由發揮
- **X**：2～3 則，字數最緊，只留最精華的一句話與比喻

## 5. 寫入檔案

資料夾：`projects/<專案>/outputs/content/<YYYY-MM-DD>-<英文短代號>/`，日期用台北時間的今天，或使用者指定的發布日。放在 `outputs/` 底下，推上 GitHub 後就會自動歸檔到成品庫，使用者能在手機上打開、複製。

每個檔案只放「要貼上的內容」與必要的小標，讓使用者能直接複製：

| 檔名                   | 內容                                             |
| ---------------------- | ------------------------------------------------ |
| `00-總覽.md`           | 核心四件事、推薦的開頭、各平台發布清單（勾選框） |
| `01-短影音腳本.md`     | 3 個開頭、分段口白與畫面、結尾                   |
| `02-TikTok.md`         | 說明文字、hashtag                                |
| `03-YouTube-Shorts.md` | 標題、說明                                       |
| `04-IG-Reels.md`       | 說明文字、hashtag                                |
| `05-IG-輪播.md`        | 每張圖卡的文字、貼文說明、hashtag                |
| `06-Threads.md`        | 3～5 則貼文，用 `---` 分隔                       |
| `07-FB.md`             | 說明文字                                         |
| `08-X.md`              | 2～3 則貼文，用 `---` 分隔                       |
| `09-小紅書.md`         | 標題、圖卡文字、內文、標籤                       |

## 6. 交付前自我檢查

逐項檢查，不符合就改：

- 每個平台講的是同一個重點、同一個比喻
- 沒有未解釋的術語；非用不可的術語旁邊有比喻
- 每則都符合 platforms.md 的字數上限（X 的中文字算 2 個字元，最容易超過）
- 用台灣用語與繁體中文（例如「影片」不是「視頻」、「品質」不是「質量」）
- 每個平台都有行動呼籲，而且和 brand.md 的名單收集方式一致
- 引用的作品、經歷都來自 brand.md；沒有依據的數字、成果、過程細節都改成【待補充】空格
- 有【待補充】空格時，在總覽檔列出來，讓本人發布前一次填完

## 7. 回報

告訴使用者資料夾路徑、推薦的開頭與理由，以及需要他親自做的事（真人形式要錄影、哪些平台要手動發）。依 JT-Projects 的規則 commit 並推到 main，成品才會歸檔。
